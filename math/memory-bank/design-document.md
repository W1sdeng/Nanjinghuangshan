# 一寸 — 产品设计文档

> **Slogan**：进一寸，有一寸的欢喜。
> **核心隐喻**：登山手账。考研/长期学习不是匀速马拉松，而是走山路。产品是你的登山手账：记录来路，标记前方，不骂你慢。

---

## 1. 产品概述

### 1.1 产品定位

一款面向长期备考与自主学习人群的**状态感知型学习管理工具**。帮助用户拆解目标、弹性执行、温柔复盘，让「推进」本身成为正反馈。

### 1.2 目标用户

- **核心用户**：考研、考公、考证等长期备考人群（备考周期 3 个月以上）
- **泛化用户**：任何有长期自主学习目标的用户（自学编程、语言、技能等）
- **用户画像关键词**：容易焦虑、计划执行波动大、启动困难、需要情绪认可

### 1.3 设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **完成定义优先** | 每项任务明确保底/标准/冲刺三档 |
| 2 | **低压力设计** | 无惩罚，不制造失败羞耻 |
| 3 | **弹性计划** | 允许延期、降级、拆分、接力 |
| 4 | **推进感优先** | 关注进度而非是否一次清零 |
| 5 | **适配状态波动** | 根据状态主动推荐任务强度 |

### 1.4 产品边界

- ✅ **做**：管理目标、任务、节奏、状态；帮助拆解、启动、推进、调整
- ❌ **不做**：内置考研内容、题库、课程；强社交、PK、排名
- 🔌 **保留**：与第三方计时、笔记工具的轻接入能力

│  └──────────┬────────────────┘   │

│  │      状态管理层             │   │
│  │  Provider / Riverpod       │   │
│  └──────────┬────────────────┘   │
│             ▼                    │
│  ┌───────────────────────────┐   │
│  │      数据持久化层           │   │
│  │  SQLite (本地) + Hive      │   │
│  └──────────┬────────────────┘   │
│             ▼                    │
│  ┌───────────────────────────┐   │
│  │      AI 集成层             │   │

│  └───────────────────────────┘   │
└─────────────────────────────────┘
```

### 2.2 数据存储方案

- **本地优先**：所有核心数据存储在设备本地 SQLite，无需登录即可使用
- **可选云同步**：用户可注册账号开启跨设备同步（iCloud / Firebase）
- **数据所有权**：用户数据完全本地可控，云端仅为备份/同步

### 2.3 AI 策略

| 场景 | 方案 | 依赖 |
|------|------|------|
| 匹配到科目模板 | 规则引擎拆解 | 本地，无需联网 |
| 未匹配到模板 | 免费 LLM API 拆解 | 需联网 |
| 离线环境 | 规则模板兜底 | 本地 |
| 状态推荐 | 规则引擎 + 可选 LLM 增强 | 核心规则本地 |

- **模型选择**：优先接入国产免费模型（如 DeepSeek 开放平台、通义千问免费额度）
- **成本控制**：每日拆解次数上限 + 缓存常见拆解结果
- **降级策略**：AI 不可用时静默切换回规则模板，不给用户报错

## 3. 功能模块详细设计

### 3.1 模块一：启动与感知

#### 3.1.1 今日一页（首页）

**设计目标**：打开即见核心，绝不信息过载。

页面布局（从上到下）：

```
┌──────────────────────────────┐
│  🌤️ 早安，小寸              │
│  "今天进一寸就好"            │
├──────────────────────────────┤
│  📋 今日必做                  │
│  ┌────────────────────────┐  │
│  │ ☐ 数学：线代第三章     │  │
│  │ ☐ 英语：阅读 2 篇      │  │
│  │ ☐ 政治：马原第二章     │  │
│  └────────────────────────┘  │
├──────────────────────────────┤
│  🛡️ 保底防线                 │
│  "今天只要完成这一件事"      │
│  ┌────────────────────────┐  │
│  │ 🔒 英语：背单词 30min  │  │
│  └────────────────────────┘  │
├──────────────────────────────┤
│  🔄 继续上次                  │
│  ┌────────────────────────┐  │
│  │ ▶ 政治：马原第二章     │  │
│  │   上次做到 40%          │  │
│  └────────────────────────┘  │
├──────────────────────────────┤
│  💬 今天感觉怎么样？          │
│  [😊 不错] [😐 还行] [😴 累] │
└──────────────────────────────┘
```

**交互说明**：
- 问候语根据时段切换（早上/下午/晚上/深夜）
- 点击「今日必做」任务 → 进入启动陪伴模式
- 保底防线自动推荐今日最易完成的任务，用户可手动更换
- 「继续上次」显示中断点进度百分比，点击定位到中断处
- 底部状态入口提供 3 个情感快速入口，点击触发状态感知流程

**状态规则**：
- 无未完成今日任务时，不显示「继续上次」区域
- 保底防线的任务默认自今日必做中选取耗时最短项
- 所有任务卡片支持 **左滑完成** / **右滑延期**

#### 3.1.2 状态感知与智能推荐

**触发时机**：

| 时机 | 触发方式 | 完整度 |
|------|----------|--------|
| 每日首次打开 | 自动弹出轻量版 | 仅主观自评 |
| 用户主动点击状态入口 | 交互触发 | 完整流程 |
| 连续 2+ 天未登录后重回 | 自动弹出完整版 | 完整流程 |
| 用户标记「未完成」 | 自动弹出一句话推荐 | 仅推荐结果 |

**感知流程**：

```
阶段一：主观自评（2 秒）
────────────────────
「你现在的精力水平？」
[🔋 充沛] [😊 正常] [😴 疲惫]

「你现在的情绪状态？」
[😌 平静] [😰 焦虑] [😞 低落]

阶段二：快速反应测试（可选，10 秒）
────────────────────
「点一下屏幕，越快越好」
3 次随机间隔点击，记录平均反应时

阶段三：综合推荐
────────────────────
输入 → 规则引擎：
  - 连续高强度天数
  - 昨日完成度
  - 当前精力 + 情绪评级
  - 反应时偏差
  - 各科目拖延率

输出推荐文案：
├─ "你最近3天都是冲刺，今天试试标准模式？"
├─ "昨天只完成了保底，今天建议先守住一个核心。"
├─ "政治拖延率较高，今天优先安排吗？"
└─ "看起来很疲惫，今天要不要休息一天？"
```

**规则引擎伪代码**：

```
function recommendIntensity(state):
    if state.days_of_high_intensity >= 3:
        return "standard", "你最近3天都是冲刺，今天试试标准模式？"

    if state.yesterday_completion == "minimal":
        return "minimal", "昨天只完成了保底，今天建议先守住一个核心。"

    if state.energy == "tired" and state.mood in ["anxious", "low"]:
        return "rest", "看起来很疲惫，今天要不要休息一天？"

    subject = state.highest_procrastination_subject()
    if subject:
        return "default", f"{subject}拖延率较高，今天优先安排吗？"

    return "standard", null
```

**推荐强度三档**：

| 强度 | 含义 | 对任务的影响 |
|------|------|-------------|
| 🟢 保底 | 守住最低标准 | 所有任务自动切换为「保底」档 |
| 🟡 标准 | 正常推进 | 保持任务原有标准 |
| 🔴 冲刺 | 挑战上限 | 活跃冲刺鼓励文案，关闭非核心干扰 |

### 3.2 模块二：执行与调整

#### 3.2.1 目标卡片系统

**数据模型**：

```
GoalCard {
  id: string
  title: string                // "线代第三章：矩阵运算"
  subject: string              // "数学"
  motivation: string           // 一句话动机，如"这章考得很频繁"
  created_at: datetime
  deadline: datetime | null
  status: 'active' | 'paused' | 'completed' | 'archived'

  // 完成标准三档
  completion_criteria: {
    minimal: string            // 保底：看完定义和例题
    standard: string           // 标准：做完课后习题
   冲刺: string                // 冲刺：完成错题整理+扩展题
  }

  // 执行状态
  current_intensity: 'minimal' | 'standard' | '冲刺'
  progress: number             // 0-100
  last_interrupt: {            // 上次中断点
    timestamp: datetime
    note: string
  }
  consecutive_days: number     // 已坚持天数
}
```

**目标卡片 UI**：

```
┌──────────────────────────────────┐
│ 📐 数学                           │
│                                  │
│ 线代第三章：矩阵运算              │
│ "这章考得很频繁"                  │
│                                  │
│ 完成标准                          │
│ ┌────────────────────────┐       │
│ │ 🟢 保底：看完定义和例题 │       │
│ │ 🟡 标准：做完课后习题  │       │
│ │ 🔴 冲刺：完成错题整理  │       │
│ └────────────────────────┘       │
│                                  │
│ 当前进度  ████████░░░░  65%      │
│ 已坚持 5 天  🔥                  │
│                                  │
│ ──── 难度滑杆 ────               │
│ 保底 ●━━━━━━━○━━━━━○ 冲刺        │
│  (当前: 标准)                     │
│                                  │
│ [▶ 开始]      [⋮ 更多]          │
└──────────────────────────────────┘
```

**难度滑杆交互**：

- 滑块三档定位：保底 / 标准 / 冲刺
- 拖动到「保底」时，完成标准自动切换为 minimal 描述
- 拖动到「冲刺」时，显示鼓励文案："今天状态不错！"
- 切换档位无负罪感设计：不记录切换历史，不提示"降级"

**进度计算规则**：

- 保底完成 = 进度 60%（达标线）
- 标准完成 = 进度 80%
- 冲刺完成 = 进度 100%
- 未达到当前强度档位标准时，按实际完成比例折算

**模板数据结构**：

      is_eligible_for_minimal: true  // 适合作为保底任务

  ]

```

**MVP 预置科目**：

| 科目 | 预置模板数量 |
|------|------------|
| 英语 | 6（背单词、阅读精读、完形、翻译、作文、真题模拟） |

| 政治 | 4（教材精读、选择题刷题、大题背诵、真题模拟） |
| 专业课 | 3（教材精读、笔记整理、真题模拟） |

**交互流程**：

```
用户新建任务 → 选择科目 → 从模板中选择 →
  自动填入完成标准三档 → 可编辑修改 → 创建完成
```

- 社区模板入口置于二级页面，默认收起
- 官方模板标记 ✅ 徽章，社区模板显示贡献者昵称
- 审核机制：后台审核上架，客户端不展示待审核模板

```

要求:
1. 输出格式为 JSON 数组，每个元素包含 day, title, estimated_minutes, minimal_goal
2. 每天预计耗时控制在 1-4 小时
3. 标注每天任务是否适合作为「保底」
4. 输出语言为中文

```

#### 3.2.4 柔性调整与未完成接力

**场景一：未完成接力**

```
今日结束 → 任务 A 完成 40%
    │
    ▼
明日自动生成接力任务：
┌─────────────────────────┐
│ 🔄 数学：线代第三章     │
│ 已完成 40%，剩余 60%    │
│ 上次中断：做到第 8 题   │
│                         │
│ [一键接续]              │
└─────────────────────────┘
```

- 接力任务保留原任务的「已坚持 X 天」记录
- 接力任务可再次被接力，不产生嵌套层级

**场景二：延时（带到明天）**

```
用户点击「带到明天」
    │
    ▼
┌─────────────────────────┐
│ ✅ 已带到明天             │
│ 火种保留：已坚持 3 天 🔥 │
│                         │
│ "休息一下，明天继续。"    │
└─────────────────────────┘
```

- 延时后任务进入第二天列表，保持原完成标准
- 连续延时超过 3 次 → 建议用户拆分或降级任务

**场景三：切道（中途切换）**

```
专注中 → 用户点击暂停
    │
    ▼
┌─────────────────────────┐
│ "累了？先做点轻松的。"   │
│                         │
│ [🔹 背 5 个单词 · 3min] │
│ [🔹 整理笔记 · 5min]    │
│ [🔹 回顾昨天 · 2min]    │
│ [✖ 直接结束]            │
└─────────────────────────┘
    │
    ▼
调剂任务完成后 → "现在感觉好点了吗？"
  ├─ [继续原来的任务]
  └─ [今天就到这里吧]
```

- 调剂任务从预置的「微小行动」池中随机推荐
- 调剂任务不计入今日必做，不触发完成度检测

**场景四：降级完成**

```
状态差 → 用户将任务强度从「标准」拖到「保底」
    │
    ▼
┌─────────────────────────┐
│ 🎉 已完成！               │
│ "虽然今天只完成了保底，   │
│  但你没有停下，           │
│  这就是推进。"            │
│                         │
│ 保底完成 ✓               │
│ 已坚持 4 天 🔥           │
└─────────────────────────┘
```

- 降级完成在数据中标记为 minimal_completion
- 回顾页显示为暖色调蓝色圆点（保底/蓝；标准/橙；冲刺/金）

### 3.3 模块三：回顾与动力

#### 3.3.1 来时路（回顾页）

```
┌──────────────────────────────┐
│  来时路          [年/月切换] │

**叙事式结语生成规则**：

```
function generateWeeklyNarrative(weekData):
    most_completed = weekData.subject_with_highest_completion()
    toughest_day = weekData.day_with_lowest_mood()
    preserved_minimal = weekData.days_of_minimal_completion()

    template = f"这周你爬完了{most_completed}，"
    if toughest_day and preserved_minimal.includes(toughest_day):
        template += f"{toughest_day}特别累但守住了保底，"
    template += "没有停。"

    return template
```

#### 3.3.3 激励体系

**徽章类型**：

| 徽章 | 条件 | 等级 |
|------|------|------|
| 🔥 持续推进者 | 连续推进 X 天 | 3天 / 7天 / 30天 |
| 🛡️ 保底守护者 | 连续保底完成 X 天 | 5天 / 15天 / 45天 |
| ⚔️ 最难攀登者 | 完成最短拖延次数最多的任务 X 次 | 5次 / 20次 |
| 🧩 拆解大师 | 成功拆解任务 X 次 | 10次 / 50次 |
| 🌄 满月行者 | 当月无断档（每天至少保底） |每月1次 |

**视觉奖励**：
- 徽章以卡片形式展示在个人中心
- 集齐 3 个同主题徽章 → 解锁主题皮肤（如「一寸光阴」皮肤）
- 解锁皮肤后可应用于 App 配色方案和图标

**设计原则**：
- 所有徽章围绕「过程质量」而非「结果」
- 无连击断掉惩罚（断掉后保留已有徽章，不显示已断）
- 不展示排行榜或与他人对比

#### 3.4.1 轻量专注计时器

**设计定位**：辅助工具而非核心功能，不强制番茄钟。

**交互说明**：

```

    │

- 放弃计时使用「换条路走」而非「放弃」

#### 3.4.2 低压提醒

**推送类型**：

| 场景 | 文案 | 时机 |
|------|------|------|
| 核心任务未开始 | "你的核心任务还在等你。" | 上午 10:00 |
| 状态提示 | "如果今天状态不好，可以先完成保底版。" | 下午 14:00 |
| 保底提醒 | "守住建底线，今天就算前进了一寸。" | 下午 18:00 |
| 深夜鼓励 | "今天辛苦了，早点休息，明天继续。" | 晚上 22:30 |
| 多日未登录 | "好几天不见了，最近还好吗？" | 3 天未登录 |

**提醒原则**：
- 频率：每天不超过 3 条
- 绝不出现「你已拖延」「落后」「警告」等词汇
- 用户可在设置中完全关闭提醒

### 5.2 文案语气规则

- 使用第二人称「你」，不使用「您」
- 避免感叹号堆砌（最多每屏 1 个）
- 不使用否定句式开头：「不要」「别」「不要」→ 改为「试试」「可以」
- 不使用恐吓或制造焦虑：「已经落后」「别人都在学」
- 不使用过度亲密称谓（亲爱的、宝宝等）
- 失败场景永远包含「但是…」结构来肯定努力

## 8. 设计原则落地检查清单

在实现每个功能时，对照以下清单检查：

- [ ] 用户是否需要看到「失败」状态？（是 → 改用温和表述）
- [ ] 这个操作是否可能让用户感到焦虑？（是 → 重新设计流程）
- [ ] 用户第一次用是否能凭直觉完成核心操作？（否 → 加引导或简化）
- [ ] 这个数据统计的目的是鼓励还是比较？（比较 → 移除）
- [ ] 这个提醒是否会打扰用户？（可能 → 降低频率或允许关闭）
- [ ] 用户能否在不登录的情况下使用核心功能？（否 → 重新架构）
- [ ] 离线情况下功能是否降级可用？（否 → 加本地兜底）
- [ ] 文案是否可能被误解为指责？（是 → 用「可以」替代「不要」）

## 9. 测试与验证策略

### 9.1 内测阶段

- **规模**：20-50 名种子用户
- **招募来源**：考研社群、小红书、即刻
- **周期**：4 周
- **关注指标**：
  - 日活 / 周活
  - 任务完成率（保底/标准/冲刺 分别统计）
  - 启动陪伴模式使用率
  - 状态感知入口点击率
  - 复盘填写率
  - 用户定性访谈反馈

### 9.2 内测验证假设

| 假设 | 验证指标 | 成功标准 |
|------|---------|---------|
| 保底防线降低启动焦虑 | 保底完成率 > 60% | 用户访谈中提及「安心」 |
| 启动陪伴模式帮用户克服拖延 | 陪伴模式 → 进入专注转化率 > 50% | 陪伴模式留存率 > 70% |
| 难度滑杆让降级无负罪感 | 滑杆使用率 > 30% | 用户反馈「没有负罪感」 |
| 状态感知推荐准确 | 用户采纳推荐比例 > 40% | 用户认为推荐「合理」 |
